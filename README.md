# 活动签到与参与统计 · HarmonyOS 应用

[![verify](https://github.com/Hunshow/harmony-checkin/actions/workflows/verify.yml/badge.svg)](https://github.com/Hunshow/harmony-checkin/actions/workflows/verify.yml)
[![License: Apache-2.0](https://img.shields.io/badge/License-Apache--2.0-blue.svg)](LICENSE)

一个面向 **鸿蒙 PC（HarmonyOS NEXT / 2in1）** 的开源示例应用：导入签到结果 → 自动检查重复记录 → 统计参与情况 → 导出汇总报表。

全程本地处理，数据不出设备。

---

## 这个 demo 解决什么问题

活动签到最常见的三个坑，这个应用一次处理掉：

| 坑 | 表现 | 本应用的做法 |
| --- | --- | --- |
| **重复导入** | 同一份签到文件导入两次，或扫码后手工又补录一次，同一个人在同一秒出现多条 | 自动识别「完全重复」（同人+同活动+同时间），标红并给出清理建议 |
| **多次签到** | 一天里进出会场多次，或签退被当成签到记进来 | 标为「多次签到」提醒人工确认，不直接当成有效出席 |
| **脏数据** | 姓名缺了、时间写成「待定」、活动 ID 是空的 | 单独归为「数据异常」，保留行号方便回原表修正 |

同时给出**数据质量分**和**出席率**，让组织者一眼判断"这份数据能不能直接用"。

## 功能一览

### 1. 导入签到结果
- 粘贴 CSV 文本即可导入，**列名自动识别**（含常见别名）
- 表头别名兼容：`活动ID` / `活动编号` / `场次ID`；`参与者ID` / `工号` / `学号` / `手机号`；`签到时间` / `打卡时间` / `创建时间`
- 时间格式兼容：`2026-10-14 09:30:00`、`2026/10/14 9:30`、`2026年10月14日 09:30`、10/13 位时间戳
- 分隔符自动嗅探：逗号 / 分号 / Tab / 竖线
- 正确处理引号转义、字段内换行、UTF-8 BOM
- 内置两套演示数据（12 行迷你示例 / 379 行完整数据），一键加载即可体验

### 2. 重复记录检查
三级判重规则，逐条可追溯到原始行号：

| 类型 | 判定条件 | 建议处置 |
| --- | --- | --- |
| **完全重复** | 同一人 + 同一活动 + **同一时间** | 直接清理 |
| **多次签到** | 同一人 + 同一活动 + 不同时间 | 人工确认是否有效出席 |
| **数据异常** | 关键字段缺失 / 时间无法解析 | 回原表修正 |

每个「人 + 活动」组合保留**时间最早**的一条作为有效出席，因此重复记录不会污染实到人数。

### 3. 参与情况统计
- **活动维度**：应到 / 实到 / 出席率 / 签到条数 / 重复数 / 异常数
- **参与者维度**：跨活动累计有效签到次数、首次与末次签到时间、重复条数
- **签到时间分布**：按小时聚合的柱状图，一眼看出签到高峰与异常集中的批量导入

### 4. 一键导出汇总
三类 CSV，带 UTF-8 BOM，Excel 双击直接打开不乱码：

- `参与明细_时间戳.csv` —— 每位参与者的有效签到次数、重复条数、时间区间
- `活动汇总_时间戳.csv` —— 每场活动的实到/应到与出席率
- `重复记录清单_时间戳.csv` —— 逐条列出重复记录、原始行号与处置建议

优先写入应用沙箱的 Download 目录（用户可在「文件管理」中直接找到）；失败时自动落到沙箱 `files/exports`，路径在界面上可一键复制。

> 本应用**不申请任何动态权限**，因此不存在「拒绝权限后导出不可用」的情况。

## 快速开始

### 1. 克隆并打开

```bash
git clone https://github.com/Hunshow/harmony-checkin.git
cd harmony-checkin
```

同一仓库镜像（开放原子 AtomGit，国内访问更快）：

```bash
git clone https://atomgit.com/gcw_husamPlM/harmony-checkin.git
```

用 DevEco Studio 打开工程根目录（含 `oh-package.json5` 的那一层），等待 Sync 完成。

### 2. 生成图标资源（可选）

图标已随仓库提供。如需重新生成（或改成自己的配色）：

```bash
node tools/gen-icons.mjs
```

脚本手写 PNG 编码，**不依赖任何图形库**，在纯 Node 环境即可运行。

### 3. 运行

- 连接鸿蒙 PC / 模拟器，点击 **Run 'entry'**
- 首次运行建议先点「加载演示数据」，可立即看到完整统计效果

### 4. 换包名（Fork 后建议修改）

`AppScope/app.json5` 里的 `bundleName` 默认是 `com.example.activitycheckin`，
改成你自己的域名倒写形式（如 `com.yourname.checkin`），避免与他人冲突。
改完后在 DevEco Studio 里重新 Sync 一次即可。

### 分层设计

```
pages/Index          ← 只负责布局与事件绑定
    ↓
viewmodel/           ← 状态（AppData）+ 动作（AppActions）
    ↓
utils/Statistics     ← 纯函数统计引擎（无 UI 依赖，可独立测试）
utils/CsvParser      ← 纯函数解析器
    ↓
model/Types          ← 纯数据定义
```

统计引擎是**纯函数**：`analyze(records, roster?) → AnalysisResult`，不碰任何系统能力。
所以它可以脱离设备、在 Node 里跑测试 —— 这正是 `tools/verify.mjs` 能成立的原因。

## 验证统计逻辑

```bash
node tools/verify.mjs
```

会在控制台输出结果，同时写入 `verify-report.txt`（UTF-8，避免 Windows 控制台中文乱码）。

覆盖 30 条断言，包括：

- CSV 解析：别名识别、分隔符嗅探、引号转义、字段内换行、BOM、空行
- 时间解析：多种格式一致性、非法值、时间戳
- 判重：完全重复 / 多次签到 / 异常的边界，同一秒多条，时间乱序
- 统计：实名去重口径、出席率计算、跨活动累计
- 鲁棒性：空输入、只有表头、2000 行以上的大数据集、结果可复现

> `tools/verify.mjs` 是 `Statistics.ets` / `CsvParser.ets` 的 **JS 同构移植**。
> 修改 ArkTS 侧算法后，请同步更新该文件，否则验证会失真。

## 输入 CSV 格式

最小可用格式（前两列必填）：

```csv
活动ID,参与者ID,姓名,部门,签到时间,签到方式
ACT-2026-001,E1001,王伟,研发部,2026-10-14 09:05:12,扫码签到
```

| 字段 | 必填 | 说明 | 可识别的列名 |
| --- | --- | --- | --- |
| 活动 ID | 是 | 唯一标识一场活动 | 活动ID、活动编号、场次ID、会议ID |
| 参与者 ID | 是 | 稳定唯一标识（工号/学号/手机号） | 参与者ID、工号、学号、手机号、用户ID |
| 姓名 | 否 | 展示用 | 姓名、参与者姓名、员工姓名 |
| 部门/分组 | 否 | 分组统计用 | 部门、班级、分组、所属部门 |
| 签到时间 | 否 | 用于判重与排序，缺失记为异常 | 签到时间、打卡时间、创建时间 |
| 签到方式 | 否 | 渠道统计用 | 签到方式、渠道、来源 |

> **为什么参与者 ID 必须稳定唯一？**
> 判重的核心是「同一个人」的识别。如果 ID 是每次签到随机生成的流水号，同一人就无法被聚合，
> 重复检测会失效。建议用工号、学号或手机号。

## 统计口径

理解这几个定义，才能看懂报表数字：

**实到人数** = 同一活动下，去重后的唯一参与者数量
> 张三签到了 3 次，实到人数只 +1。这是「出席人数」而不是「签到次数」。

**有效出席记录** = 每个「人 + 活动」组合中时间最早的那一条
> 后续的重复记录被标记但不重复计数，避免虚高。

**出席率** = 实到人数 / 名册人数
> 未导入名册时显示「未提供名册」，而不是显示 0% —— 0% 会被误读成"没人来"。

**数据质量分**（0~100）= 100 − 扣分占比 × 100
> 扣分权重：异常记录 ×10、完全重复 ×3、多次签到 ×1。
> 分数低不代表程序出错，而是提示**这份数据需要先清洗**。

## 已知限制

- 名册目前由演示数据内置生成，**尚未提供名册导入 UI**（`AppActions.importFromText` 已预留 `roster` 参数）
- 导出依赖系统「下载目录」权限，部分设备上会只落到应用沙箱
- CSV 解析按 RFC 4180 实现，未支持 `sep=` 声明式分隔符头
- 仅提供浅色主题（`EntryAbility` 中强制浅色，保证令牌一致性）

## 常见问题

**导入后数字和我手工数的不一样？**
先看「重复检查」页签。你的原始文件里很可能有重复行，应用的实到人数是去重后的结果。

**为什么有 34 条「完全重复」？**
演示数据刻意注入了 10% 的重复率来展示查重能力。用你自己的数据时这个数字取决于导出方式。

**能处理多大的文件？**
解析与分析都是单趟线性复杂度。实测 2000+ 行无压力。首次跑起来后如需支持十万行级，建议改为分片解析。

**签名怎么配？**
`build-profile.json5` 的 `signingConfigs` 为空，DevEco Studio 首次运行时会引导你自动签名。
